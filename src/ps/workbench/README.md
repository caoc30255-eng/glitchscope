# GLITCHSCOPE 正式演示流程工作台 v2.0

2026-10-27。此版本实现操作者确认一轮范围与额度、范围内逐任务预览确认、独立会话名称和统一额度账本。软件检查通过不代表新版授权与执行适配层已通过实板验收。

## 从这里开始

电脑：双击 `start_workbench.cmd`，手动打开 http://127.0.0.1:8780/ 。本机为PREVIEW，只能体验界面、旧证据和软件处理，不授予任何板卡执行权限。

右侧小额度框固定悬浮，点击可展开。第一次进入没有额度，也不会自动创建演示轮次。点击“开始本轮”，填写操作者、本轮条数、允许功能和参数范围；阅读规则、勾选并输入明确确认语句。

真实板侧部署见 `board_operations.md`。需要目标软件检查通过、原资源SHA和原编号登记完整。网页通过既有SSH转发18768→8765访问。服务仅监听127.0.0.1，保留Host/Origin与请求令牌校验。

## 哪些操作消耗额度

|操作|计数|
|---|---|
|真实扫描 / 规则 / AI的实际硬件执行|按记录占用；包含CONFIG、无扰动参照和测量|
|128×128图片真实传输|当前固定CONFIG1＋64 ITEM，任务上限65条|
|上传/灰度预览、计划编译、模型预测|0条|
|接收图片重建与三种修复、滑块对比|0条|
|64块接收策略与波形软件分析|0条|
|历史查看、报告与导出|0条|

1条额度对应一次CONFIG、参照或ITEM记录的执行尝试，不是一个毛刺或像素；一个ITEM含多个毛刺仍只占1条。

顺序扫描队列确定时，预留CONFIG＋参照＋格点×重复的确切数量；规则/AI可能追加测量，因此预留配置上限。不会因为顺序任务配置上限填44，就把实际只需3条的队列强行预留44。

任务启动先预留上述执行上限。每进入一条硬件执行尝试才计为占用；严格完成/退役后计入已完成。已完成不等于被测判据成功。已完成、执行中、UNKNOWN都是已占用的子集，不能相加。安全结束后释放明确未进入执行的预留；UNKNOWN仍占用并阻断本轮。资源是否关闭无法确认时，剩余预留继续锁定，不自动回收。

例：本轮确认100条，扫描任务上限44。启动时可用56、预留44；执行10条时可用仍56、预留34、占用10。若安全停止且确认余下未执行，可用变90。例子不构成任何实际试验授权。

旧707条和旧入口记录不会退回新账本。新账本位于原board_runs/DEMO_AUTHORITY_V1，服务重启不会恢复额度或续跑。追加额度需操作者再次明确确认；关闭本轮不删除记录。未结清任务不能强制关闭；界面没有清空账本或重置额度按钮。

## 正式操作

1. 右侧额度框确认本轮范围与上限。PREVIEW和LIVE轮次相互隔离。
2. 容错热力图中自选d/s、单点/连续/无扰动、载荷、格点、重复、顺序/规则/AI。不是固定44条；当前每扫描任务上限44。
3. 或上传图片，自选整图统一d/s和固定/随机/无扰动毛刺，预览65条计划。CONFIG固定d3/s=-1，所有64块使用同一组主d/s。
4. 输入本次任务名称。初始化前实际会话显示“尚未分配”；准备7010并确认任务条数后再启动。程序不自动重载7010。
5. 底部悬浮栏显示任务名称和实际session编号；任务记录与原件目录也保留对应关系。软件分析显示“来源会话”，不假造新硬件会话。
6. 完成后查看三判据、原始引用、图片对比、修复和波形报告；软件处理不再扣硬件额度。

## 控制与追溯

- 用户授权来自界面明确确认，后台不默认批准、不追加权限。AI只选点，不能批准、追加或训练。
- 每个任务凭据继承本轮授权，绑定版本、原资源、参数、计划SHA、上限、会话别名和任务ID，不伪造逐计划的用户/负责人批准文件。
- 逐条执行入口再次检查记录额度和真实会话绑定；扫描与图片均覆盖。原协议、RTL、bit/HWH、STM32和原生RT库不改。
- 原件、UNKNOWN、会话编号和退役事实保留；别名不是目录改名，不改变UID。
- 账本为文件锁保护的追加哈希链；损坏/丢失时拒绝新执行。记录不确定时保留占用；不会用重启或新界面绕过。
- 单机受控操作者流程，不宣称多人身份认证或硬件防篡改能力。不要同时运行其他控制入口。
